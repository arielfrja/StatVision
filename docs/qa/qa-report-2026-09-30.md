## 1. Executive Summary

StatVision is a basketball analytics tool that ingests game video, detects events with AI, and presents box scores, personnel mapping, coach reports, squad management, usage metering, and settings. The shell is calm and consistent, theme switching works, lists load, tabs switch, sign-out works. **It is not shippable.** Numbers disagree with each other on the same screen, video is always missing on READY games, identity is mostly Unknown, mobile loses the flagship Coach feature, destructive and creative actions lack visible validation, and test junk is presented as user data.

Worst single screen: `qa-14-duplicate-boxscore-game.png` — `E2E UPLOAD C`, `0 FINAL 0`, `UNKNOWN DATE`, `132 Events Detected`, HOME and AWAY both `FG 12-52 · 3P 1-12 · FT 4-8 · OR 12 · DR 21 · AST 9 · STL 2 · BLK 1 · TO 4 · PF 15 · PTS 29`. Two teams cannot shoot identically and score zero.

Second worst: `qa-03-game-detail-boxscore.png` — `6-12 FINAL` with totals `PTS 12 · +/- undefined`. The literal string `undefined` ships to coaches.

The upload test I ran (`docs/assets/demo.webm`, 343 MB, ~15 min) completed and then I deleted the resulting `QA-UPLOAD-DELETE-ME 2026-09-30` game. It reproduced every systemic issue on fresh data: premature READY, `0/0` card vs 93 events inside, `0-0 FINAL`, `UNKNOWN DATE`, no video, majority Unassigned.

**Verdict: do not demo to external coaches until data correctness gates every release.**

## 2. Scope & Method

- Acted first as an isolated external user (browser only), then used code to root-cause after evidence was secured.
- Re-logged in three times via Auth0 hosted login (`username` + `password` filled by JS, Continue clicked by UID, consent Accepted when challenged).
- Navigated almost exclusively by single-page-app clicks (`<a>` clicks, `navigation-bar-activated` dispatches, `MouseEvent` on cards) because full reloads bounce through Auth0 consent and drop deep links.
- Viewports: 1280×900 desktop, 600px narrow, 390×844 mobile. Screenshots: viewport + fullPage mixes, two element close-ups.
- Never edited data except: created nothing permanent (one whitespace probe in a dialog, cancelled), edited nothing (opened event editor, discarded), uploaded one game and deleted it.
- Read-only DOM probes: `innerText` slices, `querySelector` counts, attribute checks, `matchMedia` checks, resource timing.

## 4. Authentication & Session

### 4.1 Login works, but the edges chafe

- Hosted Auth0 login accepts the test account. One of three logins passed with no consent screen; the others required `Authorize App → Accept`.
- Auth0 inputs (`#username`, `#password`) do not appear in accessibility snapshots; I filled them by JS setter + `input` events. A password-manager / autofill user may face the same invisibility.
- `Dev Keys` warning shows on the Auth0 widget (`One or more of your connections are currently using Auth0 development keys`). Fine for dev, must never reach prod.

### 4.2 Consent loop on every full reload (P0)

Direct loads of `/games`, `/games/:id`, `/stats` bounced to `auth0.com/u/consent`, and Accept always landed on `/dashboard`, never the requested URL. SPA navigation preserved session. Consequences: refresh loses context, bookmarks/shares are useless, back-button after reload confuses, QA itself must avoid reloads. Observed repeatedly across two sessions.

### 4.3 Post-login landing ignores auth (P1)

After login the app returns to `/`, which still shows `Get Started / Sign In` for an authenticated user. I had to navigate to `/dashboard` manually (which sometimes re-challenged consent). Expected: authed `/` → `/dashboard` or an `Enter App` state.

### 4.4 Sign-out works

Header `Sign Out` → landing with both CTAs enabled; `Sign In` → Auth0. Clean.

## 5. Global Navigation & Layout

### 5.1 Four tabs, spec says six

Bottom/side nav expose Games / Teams / Usage / Settings. The functional spec (§3 of `FUNCTIONAL_DESIGN.md`) requires Performance `/dashboard`, Games, Teams, Players `/players`, Analytics `/stats`, Usage. Dashboard, Players index, and Stats are orphaned (see §19).

### 5.2 Desktop dead gutter (P1)

All desktop screenshots show content compressed into the right two-thirds with a blank left third. Root (Appendix A): desktop CSS reserves 360px for a side nav that never paints (inline `display:none` beats the responsive class). Mobile single-column is correct, proving intent. This is the first thing any desktop evaluator sees.

### 5.3 Bottom nav desync (P1)

On `/usage`, the bar marked the Settings tab active. Clicking the Settings tab or the side `Settings` link did nothing; only dispatching the bar's activation event with the settings index navigated. Plain scripted `.click()` does not fire the bar's custom activation event — real taps likely work, but the active-state logic is proven wrong in at least one state.

### 5.4 The `N` circle

A black `N` disc sits bottom-left in screenshots. It is the Next.js dev overlay, not app UI — dev-only, ignore for prod. I initially mis-filed it as an app z-index bug; correction recorded here.

## 17. Upload Test — 343 MB demo.webm End to End

**File:** `docs/assets/demo.webm`, 343 MB, ~895s duration. Title set to `QA-UPLOAD-DELETE-ME 2026-09-30` (auto-filled `demo` replaced). Screenshots `qa-21` (ready), `qa-22` (list), `qa-23` (detail), `qa-24` (delete confirm).

1. **Pick:** file input accepted the file; dropzone icon flipped to `video_file`, filename shown. Title editing via the custom text field worked with input events.
2. **Transfer:** `SECURING CLOUD UPLOAD LINK... 0%` → `STREAMING VIDEO TO CLOUD... 1%` (long dwell; reporter suspected stuck) → `10%` → completion. Percent-only, no MB/rate/ETA. A 60s status poll timed out client-side while the transfer continued — evidence the UI gives no liveness signal beyond a crawling number.
3. **Result:** list gained `SEP 30, 2026 / READY / HOME vs AWAY / QA-UPLOAD-DELETE-ME`, counters `0 / 0`. Detail `games/9a344ee4…`: `0 FINAL 0`, `UNKNOWN DATE`, `NO VIDEO`, but `93 Events Detected` within minutes — first rows `<Player #05/#03/#30/#24>`, majority `Unassigned`. READY before analysis plausibly final is premature; score/date/video never caught up during observation.
4. **No metadata asked:** league, date, teams, identity mode absent — hence defaults (`UNKNOWN DATE`, `HOME/AWAY`, arena fallback) on real data.
5. **Cleanup:** deleted via detail-page dialog; verified card gone, back to 9 cards (§18).

## 20. Design System & Visual Quality

- Calm MD3 shell, consistent cards/tabs/dialogs/progress; dark mode genuinely pleasant. Mobile single-column is the best layout.
- Token abuse: success/READY and `OPERATIONAL` render in red/pink (tertiary/error family); muted gray for healthy sync states. Inverts alarm semantics.
- Type: microcopy at 9–10px uppercase with wide tracking everywhere (timestamps, pills, footers) hurts readability; mono tabular numerals are good.
- Density: game log and box rows are appropriately tight; dashboard wastes its hero on a video void + three empty states.
- Iconography: `edit_square` on every row is tiny with tooltip-only affordance; destructive (trash) sits adjacent to primary (`Roster`) in the game header.
- Upload (`qa-11`): triple-nested bordered frames (page card > form container > dashed dropzone) look unfinished.

## 26. Product Team Critique

**You wrote KPIs, then shipped without measuring them.** `docs/product/STRATEGY.md` promises 100% reliability with a verified-vs-unverified KPI, plus turnaround, engagement, history, org, and clip KPIs. The app shows ~80% Unassigned, no verification counter, no turnaround display, no history, no orgs, no highlights — and renders `undefined` in totals. If accuracy was the North Star, acceptance was: zero Unassigned on READY, zero `undefined`, score == events. None gates release.

**Roadmap fiction.** `MASTER_ROADMAP.md` Phase 5 COMPLETED claims eFG%/TS%, frame-perfect timeline sync, replay-filtered Olympic taxonomy; I found raw `FG 1-4`, no timeline (duration 0), mixed `REBOUND` taxonomy plus `PASS/DRIBBLE` noise. AI Monitoring + Coach V1 marked done render `$0.1296` and an empty coach state. Stabilization marked done after the log admits the watchdog killed a 9/9 job pre-finalization (hand-fixed by SQL). `next_sprint.md` DEV-105/106 are checked while realtime reads `SYNCING` forever and the resume banner never dismisses.

**Spec drift approved.** `FUNCTIONAL_DESIGN.md` mandates a 6-item shell (Performance, Games, Teams, Players, Analytics, Usage); shipped 4 with Dashboard/Players/Stats orphaned, no redirects, no spec amendment. The Material-refactor merge checklist demanded desktop+mobile smoke, pricing correctness, tabs, clean console, auth flows — the gutter, model-name mismatch, missing mobile Coach tab, and console warnings prove it was not executed before landing to master.

**Design betrayal.** `DESIGN.md` promises every action/input/overlay official M3, keyboard-first, Inter/JetBrains. Shipped: native `confirm()` on list delete, mouse-only cards, text-only mobile tabs missing a feature, Roboto Flex in CSS, healthy states in red. A11y/keyboard was never a gate.

**Hygiene negligence.** Timestamped QA names, bracket hashes, E2E/Prod leftovers, UNKNOWN angle-bracket teams, duplicate squad names creatable, `demo` defaults — internal scaffolding presented as user content. No seed policy, no uniqueness, no purge, no AI-output sanitization.

**Metering before value.** Tiers/leaderboard/marketplace are unchecked boxes; the meter exists with 4-decimal money, mismatched model names, two-point charts, and enum names (`JERSEY_COLORS`, `INTERACTION_BASED`) shown to coaches. Meanwhile AI Scout narrates `defensive inconsistencies` over 0-0 duplicated data. Theater over correctness.

**Process provocations borne out by the log:** repeated `Implementation complete … Ready for QA` with unchecked QA lists; promotion to master on a `direct-to-master workflow` with E2E skipped on-platform, webhook tests blocked, `npm audit 33 vulns (20 high)` acknowledged and carried. Green type-check became a proxy for done.
